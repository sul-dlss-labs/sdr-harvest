## Setup

Dependencies (beautifulsoup4, pillow) are managed by uv in the repository's
`pyproject.toml`. From the repository root:

    uv sync

Then in LM Studio:

1. Load the `chandra-ocr-2` model (set temperature to 0.0, and disable "Enable Thinking").
2. Start the local server (Developer tab), which listens on
   `http://127.0.0.1:1234` by default.
3. Check the model id with `curl http://127.0.0.1:1234/v1/models`. If it
   isn't `chandra-ocr-2`, update `MODEL` in `ocr.py`.

## Running

From this `ocr/` directory:

    uv run python ocr.py kr104zb7305

This will:

1. Fetch `https://purl.stanford.edu/kr104zb7305.json` and find every
   `image/jp2` file in the structural metadata.
2. Download each page from the IIIF image server scaled so the long edge is 1024px (IIIF size `!1024,1024`), e.g.
   `https://stacks.stanford.edu/image/iiif/kr104zb7305/kr104zb7305_0001/full/!1024,1024/0/default.jpg`
3. Send it to the model with `prompt.txt` and check the response is layout
   HTML (top-level `<div data-bbox=...>` blocks).
4. Convert the HTML to ALTO with `html2alto.py`, scaled to the full-size jp2
   dimensions, and write it to `kr104zb7305/kr104zb7305_0001.xml`, etc.

Pages that already have an `.xml` file are skipped, so you can rerun the
command to retry pages that failed. Failed pages are listed at the end and
the script exits non-zero.

The model's HTML is cached as `kr104zb7305/kr104zb7305_0001.html`, etc. When
a cached HTML file exists, the OCR step is skipped and the ALTO is rebuilt
from it, so you can change the conversion without rerunning the model.

### Blocks-only ALTO

By default `html2alto.py` estimates line and word positions inside each
block (one line per `<p>`, word widths from letter counts). Those positions
are guesses. With `--blocks-only`, only blocks get coordinates; `TextLine`
and `String` carry the text with no position (valid ALTO v4), and lines
follow the HTML's `<p>`, `<li>` and `<br>` structure:

    uv run python ocr.py kr104zb7305 --blocks-only --out kr104zb7305-blocks

To convert ALTO made before HTML caching existed, strip the estimated
positions instead (lines are not split at `<br>`):

    uv run python strip_positions.py kr104zb7305 kr104zb7305-blocks

## Line-level OCR with Qwen3-VL

`--engine qwen` sends each page to `qwen/qwen3-vl-4b` with the prompt in
`prompt_qwen.txt`, which asks for a JSON array of
`{"text": ..., "bbox_2d": [x1, y1, x2, y2]}`, one entry per text line. The
boxes are on a 0-1000 scale, like Chandra's, and are scaled to the full-size
jp2.

    uv run python ocr.py kr104zb7305 --engine qwen

This writes `kr104zb7305-qwen/kr104zb7305_0001.xml`, etc., and caches the
parsed lines as `kr104zb7305-qwen/kr104zb7305_0001.json`. `lines2alto.py`
does the conversion: line boxes come from the model, lines are grouped into
blocks at large vertical gaps, and word positions inside a line are estimated
from letter counts. Add `--blocks-only` to keep the block and line boxes but
leave words without a position. Use `--model` to try another model id with
the same prompt, and `--prompt FILE` to try another prompt
(`prompt_qwen_tight.txt` and `prompt_qwen_paragraphs.txt` are included; the
paragraph format, blocks each holding their lines, keeps the model's blocks).

## Line-level OCR with PaddleOCR-VL

`--engine paddle` uses PaddleOCR-VL 1.6
(https://huggingface.co/jmbarrancoidener/PaddleOCR-VL-1.6-mlx-8bit, loaded in
LM Studio as `paddleocr-vl-1.6-mlx`) in its text spotting mode. The prompt is
the model's fixed task string `Spotting:`, and it replies with one line of text
per row followed by the four corners of the line as `<|LOC_n|>` tokens on a
0-1000 scale. The default image size for this engine is 1440px on the long
edge, about the 1.6 megapixels PaddleOCR's own pipeline uses for spotting.

    uv run python ocr.py kr104zb7305 --engine paddle

Output goes to `kr104zb7305-paddle/`. It is the most accurate engine here for
line positions and indents, and the fastest (about 5 seconds a page).

## Options for any engine

- `--pages 5,7` only processes those page numbers.
- `--image-size N` sets the long edge of the image sent to the model.
- A non-default `--model`, `--prompt` or `--image-size` gets its own output
  folder, e.g. `kr104zb7305-qwen-qwen3-vl-8b-tight-1536/`, so runs don't reuse
  each other's cached results.
- If the output hits `max_tokens`, the raw response is saved next to the
  output as `<page>.response.json`.

## Scoring line positions against ABBYY

    uv run python score_lines.py kr104zb7305 kr104zb7305-qwen kr104zb7305-paddle --pages 1,2,3

Matches each model line to the ABBYY line in SDR with the most similar text
and reports the average and worst vertical error in full-size pixels (overall,
for paragraph first lines and for other lines), how many of ABBYY's indented
first lines the model also indents, and, for block-structured output, how
many paragraph starts begin a model block. Pages with little ordinary text,
like tables and figures, can't be scored.

## Viewing the results

    uv run python build_viewer.py kr104zb7305
    open kr104zb7305-viewer.html

This builds a single offline HTML file with every page scan and both the
Chandra ALTO and the ABBYY ALTO already in SDR drawn over it. Pick layers to
show, hover a box to see its text and coordinates, and search for a word.
Use `--alto DIR` to view a different set of files and `--label` to name them, e.g.

    uv run python build_viewer.py kr104zb7305 --alto kr104zb7305-blocks --out kr104zb7305-blocks-viewer.html
    uv run python build_viewer.py kr104zb7305 --alto kr104zb7305-qwen --label Qwen --out kr104zb7305-qwen-viewer.html

Add `--pages N` to include only the first N pages.

## Converting a single page by hand

    uv run python html2alto.py output.html page.png > page.alto.xml
    uv run python html2alto.py --blocks-only output.html page.png > page.alto.xml
    uv run python lines2alto.py page.json page.png > page.alto.xml
